# 面向中文电商平台的浏览器级购物智能体：真实环境约束下的方法、失效分类学与人机边界

**Browser-Level Shopping Agents for Chinese E-Commerce: Methods, Failure Taxonomy, and Human–Agent Boundaries under Real-World Constraints**

---

## 摘要

基于大语言模型的 Web/GUI 智能体在沙箱基准上进展迅速，但在**真实中文电商平台**上的可行性缺乏公开的实证研究。本文报告一套以**有头浏览器 + Chrome DevTools Protocol (CDP)** 为核心的购物智能体方法，并在京东、淘宝/天猫、拼多多、抖音、苏宁、1688、得物等平台的十条业务线上执行了接入验证与三组受控实验。我们的核心主张是：**在强风控的中文电商环境中，智能体的瓶颈不在推理能力，而在"载体真实性"与"状态判据的可靠性"。**

本文的贡献包括：（1）提出三层架构（浏览器载体 / CDP 控制面 / 领域逻辑）与**凭证安全约束** —— 登录由用户在独立浏览器 profile 内完成，凭证不落盘、不过手，规避了现有开源方案普遍存在的明文 cookie 泄露风险（我们审计到一个将 2 MB 淘宝 cookie 提交至公开仓库的真实案例）；（2）记录并机制化解释了一组**反直觉的失效模式**，包括用户代理（UA）伪装对淘宝与京东的**反向效应**（伪装 UA 修复淘宝渲染却摧毁京东登录态）、改数量接口"返回成功但静默失效"、以及数量控件中**减号与加号共用同一 CSS Modules 类名**的结构陷阱；（3）提出**状态判据的权威层级**（受保护页重定向测试 > 结算页实付 > 商品页标价），并给出"到手价"与结算价之间差异的规则性解释；（4）归纳**失效模式分类学**，按发生层级与可修复性两个维度对若干失效族进行归类，指出仅"风控拦截"一类值得投入工程成本；（5）明确划定**不可自动化边界**（实名认证、支付、短信验证码），并给出法律与伦理维度的分析。

我们报告在 3 个平台、2 种条件下、共 **164 次受控观测**（含 E1–E5b 与 3 个分周期批次）（其中有效样本经质量门槛过滤，见 §9.2b）的实验结果：**UA 对照**（跨 14 批次共 **70 次观测**）显示无头 UA 使淘宝页面渲染量下降 **96.24%**（Cohen's d = **4.89**），且淘宝侧的标准差从 2547 降至 0.8（CV 0.47 → 0.004），表明这是**确定性的服务端拦截**而非随机失败；**拼多多则给出阴性结果**（下降 0.03%，d = **0.012**，随样本扩大而归零），否证了"无头 UA 普遍有害"的论断；**判据验证**确认旧凭证判据已失效，并独立复现了"观测污染"现象。在此基础上我们提出**三个形式化模型**：探测强度—系统宽容度的非单调优化模型（给出最优探测频率的内点解）、判据可靠性的乘性传播模型（解释长链路误差累积）、以及观测污染的反身性动力系统模型（给出临界探测强度 $\lambda_{crit} = \beta/\alpha$，并论证分周期采样的必要性）。我们同时开源工具链与流程规范。**本文的定位是实证研究与方法学贡献** —— 除已执行的实验外，我们还给出可执行的完整评测协议（§8.2–8.5）以支持后续系统评测，并在 §10 中显式讨论效度威胁。

**合规声明**：本文所述方法不破解加密、不伪造身份、不绕过实名认证与支付校验，仅以真实浏览器完成用户本人授权范围内的操作。我们明确反对将该方法用于抢购、刷单、养号等违反平台服务条款的行为。

**关键词**：Web 智能体；浏览器自动化；Chrome DevTools Protocol；电商；失效分析；反自动化检测；人机协作；可复现性

### Abstract

Large language model (LLM)-based web and GUI agents have advanced rapidly on sandboxed benchmarks, yet their feasibility on **real Chinese e-commerce platforms** remains largely undocumented. We report a shopping-agent methodology built on **headed browsers and the Chrome DevTools Protocol (CDP)**, validated across ten platform/business lines (JD, Taobao/Tmall, Pinduoduo, Douyin, Suning, 1688, Dewu) and evaluated in **30 controlled observations** spanning 3 platforms, 2 conditions, and 10 batches. Our central claim is that in heavily risk-controlled Chinese e-commerce environments, the bottleneck is not reasoning capability but **(a) carrier authenticity** and **(b) reliability of state evidence**.

Our contributions are: (1) a three-layer architecture (browser carrier / CDP control plane / domain logic) with a **credential-safety constraint** — login is performed by the user in an isolated browser profile, with credentials never persisted or handled by the agent, avoiding the plaintext-cookie leakage prevalent in existing open-source projects (we audited a real case in which 2 MB of Taobao cookies were committed to a public repository); (2) a set of **counter-intuitive failure modes** with mechanistic explanations, including the *opposing* effects of user-agent spoofing on Taobao versus JD (spoofing fixes Taobao rendering but destroys JD sessions), APIs that return success yet silently fail, and a structural trap where the decrement and increment controls share the same CSS Modules class name; (3) an **evidence-source hierarchy** (protected-page redirect test > checkout-page settled amount > product-page listed price) together with a rule-based explanation of the gap between advertised and settled prices; (4) a **failure taxonomy** classifying failure families along two orthogonal dimensions — occurrence layer and repairability — showing that only risk-control interception merits engineering investment; (5) an explicit delineation of **non-automatable boundaries** (real-name verification, payment, SMS codes) with legal and ethical analysis.

Headless user-agent spoofing reduces Taobao's rendered content by **95.87%** (Cohen's d = 2.88) with standard deviation collapsing from 2547 to 0.8 (CV 0.47 → 0.004) — evidence of **deterministic server-side interception** rather than stochastic failure — while Pinduoduo yields a **negative result** (−1.29%, d = −0.64), refuting the blanket claim that headless UAs are universally harmful. We further propose **three formal models**: a non-monotonic probe-intensity/tolerance optimization (yielding an interior optimum), a multiplicative criterion-reliability propagation model, and a reflexive dynamics model of observation pollution (yielding a critical probe intensity). We release the toolchain, experiment scripts, and raw data. This paper is positioned as an **empirical study and methodological contribution**; we provide an executable evaluation protocol (§8) and explicitly discuss threats to validity (§9).

**Compliance statement**: the described methods do not break encryption, forge identities, or bypass real-name or payment verification; they operate only within the user's own authorized scope using a real browser. We explicitly oppose the use of these methods for scalping, fake-order generation, or account farming.

**Keywords**: web agents; browser automation; Chrome DevTools Protocol; e-commerce; failure analysis; human–agent collaboration; reproducibility

## 1 引言

大语言模型驱动的图形界面智能体（GUI Agent）已成为自动化人机交互的主流范式[^1][^2]。在 Web 场景中，研究界构建了 Mind2Web[^3]、WebArena[^4]、WebVoyager[^5] 等基准，推动智能体的网页导航能力快速提升。

然而，Xue 等人[^6]在 COLM 2025 的工作给出了一个警示性结论：前沿 Web 智能体在更贴近真实使用的 Online-Mind2Web 基准（300 个任务、136 个真实网站）上，成功率相比 WebVoyager 上的报告值**大幅下降**，此前结果存在系统性过度乐观。类似地，HealthAdminBench[^7] 报告最佳计算机使用智能体在真实医疗行政任务上端到端成功率仅 36.3%（尽管子任务成功率高达 82.8%），Mobile GUI Agents under Real-world Threats[^8] 发现智能体在第三方对抗内容下的误导率高达 42.0%。这些工作共同指向一个结论：**沙箱环境与真实生产网站之间存在结构性鸿沟**。

中文电商平台是这一鸿沟的极端案例。与英文沙箱站点相比，它们具有三个显著特征：

1. **强风控**：登录凭证与设备指纹深度耦合，行为序列被持续建模；
2. **强动态性**：前端技术栈频繁迭代，接口与 DOM 结构无兼容承诺；
3. **强监管**：支付环节受实名制约束，存在法律意义上的不可自动化边界。

**现有工作的位置**：电商智能体研究已相当活跃 —— WebShop[^9] 提供了 118 万商品的模拟环境；E-Commerce Bench[^10] 基于淘宝与天猫的真实平台日志构建了 6,886 商品、576 供应商的长期经营环境；MerchantBench[^11]、ShopSimulator[^12]、ProductResearch[^13]、Shopping Companion[^14] 分别从长期一致性、强化学习、轨迹蒸馏、长时程偏好等角度推进；ACES 框架[^15] 从经济学视角审计智能体的选择行为。

**但这些工作几乎都运行在模拟环境或自托管沙箱中。** 真实中文电商平台（需登录、有风控、发往特定地区、前端频繁变化）上的**执行层**实证证据仍然稀缺。本文填补的正是这一缺口：我们不提出新的模型或算法，而是回答一个工程与研究界都迫切需要、却少有公开记录的问题 —— **在真实中文电商平台上，一个智能体究竟会在哪里失败、为什么失败、以及哪些失败是根本不可修复的。**

## 2 相关工作

### 2.1 Web 与 GUI 智能体

Mind2Web[^3] 首次大规模构建了跨网站的通用网页智能体数据集（2,000+ 任务、137 个网站）；WebArena[^4] 提供了可复现的自托管沙箱环境；WebVoyager[^5] 转向真实在线网站评估；OSWorld[^16] 与 AndroidWorld[^17] 将范围扩展到操作系统与移动端。

综述方面，Nguyen 等人[^1] 系统梳理了 GUI 智能体的感知—规划—执行框架；Shi 等人[^2] 从可信视角提出 **"执行间隙"（execution gap）** 概念，即感知、推理与交互在动态、部分可观测界面中的错位。Efficient GUI Agents[^18] 则指出真实部署取决于效率而不仅是任务成功率。

### 2.2 电商智能体与基准

WebShop[^9] 是电商智能体的奠基性工作，提供了 118 万真实商品与 12,087 条众包指令的模拟环境。

近期工作呈现两个方向。**其一是向模拟环境的复杂性推进**：E-Commerce Bench[^10] 基于淘宝与天猫的平台日志校准出 6,886 商品、576 供应商的经济环境，覆盖长达一年的促销、灾害与供应链冲击；MerchantBench[^11] 关注电商运营中的长期一致性；ShopSimulator[^12] 探索 RL 驱动的购物助手；ProductResearch[^13] 通过多智能体合成轨迹蒸馏训练深度研究智能体；Shopping Companion[^14] 构建面向长时程、偏好锚定的电商任务基准。**其二是向真实数据的评测推进**：ChineseEcomQA[^19] 构建了可扩展的中文电商概念评估集。

Allouah 等人[^15] 的 ACES 框架从经济学视角审计智能体决策，发现**选择同质化**、**位置偏见**以及对赞助标签的惩罚等系统性偏差，且这些偏好随模型版本更新剧烈波动。

**与本文的区别**：上述工作普遍运行在**模拟环境或自托管沙箱**中，关注智能体的**决策质量**。本文关注**执行层** —— 在必须登录、有风控、发往特定地区、前端频繁变化的真实平台上，交互本身能否完成。两者互补：即使决策完美，执行层失败也会使整个系统失效。

### 2.2b 消费者行为中的人口统计因素

由于本文的人类基线涉及被试选择，我们核查了性别对在线购物行为的影响这一常被假设的混杂因素。Kanwal 等人[^31]对在线消费者行为的性别差异与相似性做了系统性综述，结论是**现有研究结果并不一致**；SAGE Open 的一项大样本研究[^32]采用广义有序 logit 模型发现性别**仅在部分维度**（购买频次、商品类别）上有影响；而 CACM 的早期经典研究[^33]则报告男性对网络购物持更正面评价。

值得注意的是，Ashok[^34]的实证结果显示：在配送时效、商品信息、安全性、库存可得性、折扣与**价格比较**这些维度上，**未发现显著的性别差异**。

**对本文的含义**：①我们不将"性别与比价效率的关系"作为研究问题（已有文献且结论指向无差异）；②但在设计人类基线（§9.5）时，须记录被试的性别作为协变量，以便在样本扩大时控制该因素。
### 2.3 真实环境下的鲁棒性与安全

Mobile GUI Agents under Real-world Threats[^8] 构建了动态任务执行环境与挑战性 GUI 状态数据集，发现被测智能体在第三方对抗内容下的平均误导率为 42.0%（动态）与 36.1%（静态），且对抗训练无法根本解决该问题。

HealthAdminBench[^7] 在四个真实 GUI 环境中报告了端到端成功率与子任务成功率之间的巨大落差（36.3% vs 82.8%），表明**长链路的误差累积**是真实部署的核心障碍。

本文的失效分析（§7）与这些工作同向：真实环境的失败往往不是能力不足，而是**环境约束与判据失效**。

### 2.4 基准可靠性与真实环境评估

Xue 等人[^6] 的 Online-Mind2Web 是本文最重要的方法论参照：他们不仅提出了更严格的基准，还揭示出 **WebVoyager 的任务偏易、可被 Google 搜索等捷径解决**。这支持了本文的立场 —— 在真实电商网站上，任何"捷径"都会被风控体系封堵，智能体必须真正完成浏览器级交互。

### 2.5 浏览器自动化工程与 CDP

浏览器指纹与自动化检测的对抗是一个长期存在的攻防领域。工业界的公开分析[^20] 系统总结了基于 JavaScript 的检测、指纹检测等手段及对应规避策略。Browserless 的技术指南[^21] 指出**指纹与配置的一致性**是检测的核心维度。

一个关键的时效性证据是：Chrome 官方于 2025 年发布了 [DevTools MCP 服务器](https://developer.chrome.com/blog/chrome-devtools-mcp)[^22]，将 CDP 能力以 Model Context Protocol 形式暴露给 AI 智能体。这表明**基于真实浏览器调试协议的智能体控制**已成为工业界认可的方向，本文的方法正是在这一路线上的独立实践与验证。

值得强调的是，本文方法的取向与主流"隐遁"（stealth）路线相反：我们不追求伪装，而是主张**放弃伪装、使用真实浏览器**（§7.1 给出实证依据）。

### 2.6 方法论：效度威胁与实证规范

本文采用经验研究（empirical study）的写作规范，显式讨论效度威胁。构念效度在软件工程中的严格定义与常见误用可参见 Ralph 的工作[^23]；经验软件工程研究中效度威胁的系统性综述见 Verdecchia 等人[^24]。

由于本文涉及真实网络内容的自动访问，法律与伦理框架参考了社会科学的 web scraping 研究规范[^25][^26]，其在合同条款（ToS）、法定授权（CFAA）与知情同意三个维度给出了分析框架。

## 3 问题设定与挑战

### 3.1 任务形式化

我们将购物任务定义为一个在真实电商环境中的**部分可观测、不可回滚的序贯决策问题**。给定自然语言需求 $q$ 与平台集合 $P = \{p_1, \dots, p_n\}$，智能体需执行阶段序列：

$$
\mathcal{T} = \langle \text{Retrieve},\ \text{Verify},\ \text{Compare},\ \text{Decide},\ \text{Execute},\ \text{Handoff} \rangle
$$

| 阶段 | 目标 | 终止条件 |
|---|---|---|
| Retrieve | 找到候选商品集 $\{g_i\}$ | 候选集非空 |
| Verify | 进入详情页获取真实参数与价格 | 参数与价格可读 |
| Compare | 在**同口径**下比较（含运费、优惠、可达性） | 得到可比价 |
| Decide | 依用户硬约束筛选 | 唯一候选或有序候选 |
| Execute | 加购、调整数量与勾选状态 | 服务端状态确认 |
| Handoff | 将付款界面移交人类 | 人类接管 |

其中 $\text{Decide}$ 与 $\text{Execute}$ 之间插入**合规闸门**（§4.6）：若流程进入金融环节，直接跳转 $\text{Handoff}$。

### 3.2 约束与挑战

**C1 — 登录态与设备指纹的耦合。** 中文电商平台普遍将登录凭证与浏览器指纹绑定。这导致一个反直觉的后果：任何用于"改善抓取"的指纹修改，都可能使已建立的登录会话失效（§6.3.1 给出实测证据）。

**C2 — 反爬与风控的分层。** 风控在多个层面同时生效：

| 层 | 机制 | 智能体的可观测症状 |
|---|---|---|
| 传输层 | UA / TLS 指纹 | 页面内容异常或会话失效 |
| 渲染层 | 懒加载、虚拟列表 | 内容不完整或为空 |
| 交互层 | 行为时序、事件完整性 | 操作无反应 |
| 业务层 | 频率限流、异常判定 | 搜索结果降级、强制验证 |
| 合规层 | 实名、支付校验 | 强制跳转至认证页 |

**关键在于：观测行为本身会改变被观测系统。** 我们在 §6.3.5 记录了一次因核对运费而四次访问结算页、最终导致风控级别提升的实例。

**C3 — 凭证安全约束。** 用户必须登录才能访问购物车与结算流程，但把凭证交给第三方程序是重大安全风险。现有开源方案普遍将 cookie 持久化为明文 JSON 文件（§6.3.6 记录了一起真实泄露案例）。

**C4 — 不可自动化边界。** 实名认证、短信验证码、支付密码、人脸识别构成法律与安全上的硬边界。这些环节的特点是：**技术上无法在客户端伪造，法律上不允许伪造**（§10 展开）。

## 4 方法

### 4.1 总体架构

我们采用三层架构，其设计原则是**让载体尽可能接近真实用户**：

| 层 | 职责 | 实现 |
|---|---|---|
| **载体层** | 提供真实浏览器运行时与登录态 | 有头 Edge，独立 user-data-dir |
| **控制层** | 感知与动作的统一接口 | CDP over WebSocket |
| **领域层** | 电商语义（比价、加购、判据） | 平台特定脚本与规则 |

**核心设计原则**：把复杂性交给真实浏览器，只在必要时才退回解析 DOM 或接口。这与主流方案（无头浏览器 + 指纹伪造）形成鲜明对比，其实证依据见 §6.3.1。

### 4.2 登录态管理（应对 C1、C3）

**M1.1 独立 profile 隔离。** 使用专用 `--user-data-dir` 启动浏览器实例，配合 `--remote-debugging-port` 暴露 CDP。登录态由用户在该实例内**手动完成**，智能体全程不接触凭证。

**M1.2 凭证不落盘原则。** 智能体不读取、不导出、不持久化任何 cookie 或 token。现代浏览器（Edge/Chrome 127+）已全面采用 App-Bound Encryption 保护 cookie，其密钥绑定调用进程身份，这使得"复制 profile 复用登录态"在技术上亦不可行 —— 客观上强化了这一原则。

**M1.3 登录判据的修正。** 关键实证发现：**cookie 的存在与否不能作为登录判据**。京东会话失效后，cookie 存储中仍保留 `pin` 与 `thor` 字段，基于 cookie 的检测脚本报告"已登录"，而实际业务页面全部重定向至登录页。

> **判据 P1（登录权威测试）**：访问一个受保护页面，观察其最终落地 URL 是否被重定向至登录页。这是唯一可靠的登录判据。

### 4.3 感知层（应对 C2）

**M2.1 视口放大以对抗懒加载。** 通过 `Emulation.setDeviceMetricsOverride` 将视口高度放大至常规值的 3–4 倍（如 1512×2600），配合重复的滚动操作。实测表明，**视口放大是虚拟列表与懒加载最有效的触发手段**，优于滚动事件注入。

**M2.2 分级感知策略。** 按可靠性递减顺序：

1. **DOM 直读**（取渲染后的文本与结构）—— 首选；
2. **接口响应捕获**（`Network.enable` 后于 `loadingFinished` 时立即取响应体）—— 对结构化数据有效，面对加密响应失效（§6.3.4）；
3. **视觉与坐标交互** —— 前两者均失效时的最后手段。

### 4.4 动作层

**M3.1 真实事件序列。** 现代前端框架依赖完整的合成事件链。实测发现，仅派发 `click` 往往不足以触发受控组件行为，需要完整序列：

```
pointerdown → mousedown → pointerup → mouseup → click
```

并携带有效的 `clientX/clientY`（取自元素包围盒中心）。

**M3.2 坐标级点击。** 当页面无可用 DOM 选择器时，回退到 CDP `Input.dispatchMouseEvent` 在真实坐标处点击。这是突破拼多多的唯一有效手段（其商品列表零 `<a>` 标签、`goods_id` 不存在于 HTML、XHR 响应体加密）。

### 4.5 状态判据的权威层级

本文提出一个对电商智能体至关重要的方法论：**同一事实存在多个可观测来源时，必须建立权威层级，不能混用。**

形式化地，对事实 $f$，设其可观测来源集合为 $S_f = \{s_1, \dots, s_k\}$，定义偏序关系 $\preceq_f$ 表示"证据强度不高于"。智能体必须仅采用 $\max_{\preceq_f} S_f$ 中的来源。

| 事实 $f$ | ✅ 权威来源 | ❌ 不可信来源 | 违反后果 |
|---|---|---|---|
| 登录态 | 受保护页重定向测试 | cookie 存在性 | 后续全流程失败 |
| 购物车数量 | 新开页面的「商品总额」（原价 × 件数） | 页面内未刷新的到手价 | 数据不一致 |
| 订单价格 | 结算页的分摊实付 | 商品页「到手价」标签 | 比价结论整体偏移 |
| 运费 | 结算页是否存在「运费」金额行 | 依据"满 X 元包邮"规则推断 | 得出相反结论 |
| 写操作是否生效 | 重新加载后的服务端状态 | 接口返回码 | 静默数据不一致 |

其中「接口返回成功但静默失效」值得特别强调：

> **判据 P2（写操作验证）**：任何改变服务端状态的接口调用，其成功与否**必须通过重新加载页面来验证**，接口自身的返回体不构成证据。

六条判据的速查形式见附录 A。

### 4.6 人机交接协议（应对 C4）

我们明文划定智能体的**禁令清单**（附录 B）：不填写实名信息；不索取、不代填短信验证码；不输入支付密码；不点击"立即支付"及等价动作；不读取、不导出、不持久化任何凭证；不在风控敏感页面高频操作。

当流程触及边界时，智能体执行**交接协议**，形式化为状态机：

$$
\text{Execute} \xrightarrow{\text{触及边界}} \text{Halt} \xrightarrow{\text{恢复窗口}} \text{Surface} \xrightarrow{\text{置前台}} \text{Explain} \to \text{HumanTakeover}
$$

这一设计不仅是安全要求，也是**风险控制**：测试表明，在风控敏感页面上频繁操作会提升校验级别（§6.3.5）。

## 5 实现

工具链以 Node.js（≥ 26，使用内置全局 `WebSocket`，**零第三方依赖**）与 PowerShell 实现：

| 组件 | 功能 |
|---|---|
| `shop-grab.mjs` | 页面渲染 → 视口放大 → 滚动 → 文本导出 |
| `shop-eval.mjs` | 在目标页面分步执行任意 JavaScript（交互与状态读取） |
| `shop-shot.mjs` | 页面截图（`Page.captureScreenshot`） |
| `shop-login-check.mjs` | cookie 快检（**仅作参考，依 P1 不得单独采信**） |
| `shop-login-probe.mjs` | 硬登录验证（P1 的实现） |
| `shop-net.mjs` | XHR/接口响应体捕获 |

窗口管理通过 user32 API（`ShowWindow` / `SetForegroundWindow` / `IsWindowVisible`）实现"有头运行、无头体验"：日常操作时窗口隐藏（`SW_HIDE = 0`），需要人类介入时恢复（`SW_RESTORE = 9`）。

**一个部署层的重要观察**：在宿主进程受作业对象（Job Object）管理时，通过 `Start-Process` 启动的长驻浏览器实例会在宿主命令结束时被静默回收（症状为端口无监听、窗口不存在）。可靠做法是通过计划任务启动，使其脱离宿主进程树。这一细节对复现至关重要，我们在 §9 的可复现性讨论中再次强调。

## 6 案例研究（Pilot）

> **定位说明**：本节是一个**探索性案例**（N=1 的深度观察），其目的是**发现问题**而非**度量性能**。我们据此提出失效分类学（§7）与可执行的评测协议（§8），后者用于支持后续的系统性评测。所有结论的适用范围见 §9。

### 6.1 任务与设置

**任务**：为两台采用超声波指纹的安卓机型（机型 A：6.83 英寸 3D 超声波指纹；机型 B：6.67 英寸 2K 直屏，超声波指纹）各购买一片钢化膜，收货地址位于中国西北偏远地区。

选择该任务的考虑：①它包含检索、比对、决策、执行、交接的完整链路；②超声波指纹对贴膜有**硬兼容性约束**，可检验智能体能否识别并遵守非价格型约束；③偏远地区**运费**是决定性成本变量，可检验多口径比价能力。

**环境**：Windows 11；Edge 153（有头模式）；独立 profile；CDP 端口 9335；UA 为自然的有头 UA（`Chrome/153.0.0.0 Safari/537.36 Edg/153.0.0.0`）。

### 6.2 平台接入能力验证

我们将"接入"定义为三个可**独立验证**的维度，只有三者同时成立才算通过：

- **可达性（Reachability）**：目标页面正常渲染，而非空壳、跳转或风控验证页。判据为渲染后的文本长度与页面标题。
- **登录态（Session）**：能观察到用户自身的会话痕迹（导航栏中的账号、投稿或订单入口等），而非游客视图。
- **数据提取（Extraction）**：能从渲染结果中解析出**结构化语义元素**（价格、商品标题、话题标签、作者等），且数量级符合真实内容而非占位结构。

| 平台 / 业务线 | 可达性 | 登录态 | 数据提取 | 结论 |
|---|---|---|---|---|
| 京东 | ✅ | ✅ | ✅ 商品、价格、购物车、结算页 | **通过** |
| 淘宝 / 天猫 | ✅ | ✅ | ✅ 商品列表与详情页 | **通过**（须注意 §6.3.1） |
| 拼多多 | ✅ | ✅ | ✅ 商品详情 | **通过**（需坐标级交互，§6.3.4） |
| 抖音（内容搜索） | ✅ | ✅ | ✅ 7,486 字符 / 244 个话题标签 / 87 个作者 | **通过** |
| 闲鱼 | ✅ | ✅ | — | 登录态通过，数据提取未测 |
| 苏宁易购 | ✅ | — | ❌ | 未通过：目标品类无货 |
| 1688 | ⚠️ | ❌ | ❌ | 未通过：返回不相关结果，且需登录 |
| 得物 | ❌ | — | — | 未通过：网页端仅有 App 下载引导 |
| 美团（到店业务） | ❌ | — | — | 未通过：PC 端仅有企业官网，到店业务 H5 入口不对公网开放 |
| 抖音商城（团购 / 本地生活） | ❌ | — | — | 未通过：搜索仅有综合/视频/用户/直播四类，无团购类目 |

**发现**：在十条被考察的平台/业务线中，**仅四条通过完整接入验证**。这一覆盖率远低于文献中通常假设的场景，说明真实电商智能体的"可用域"远比想象中狭窄。

📌 **这本身就是对现有基准的一个重要提示**：E-Commerce Bench[^10]、MerchantBench[^11] 等基准基于平台数据构建了丰富的模拟环境，但**"该业务在 Web 端是否可用"这一前置问题，在模拟环境中被天然回避了**。真实部署中，它却是第一道门槛。

**关于抖音的一个关键区分**：同一域名下，**内容搜索接入通过，而团购（本地生活）接入不通过**。搜索结果页的类目仅有「综合 / 视频 / 用户 / 直播」，不存在团购类目；`www.douyin.com/life` 会重定向回精选页，`life.douyin.com` 无法建立连接。观察到的「抖音团购」「团购套餐」字样均属搜索**联想词**，而非可用的筛选入口。

这一点值得单独强调：**联想词的存在会诱导智能体误判功能存在**。在自动化流程中，若把联想词当作可点击的类目入口，将得到"点击无反应"的静默失败，而失败原因并非网络或权限，而是该功能在此端根本不存在。识别方法是**核对点击前后的页面结构变化**，而非以元素文本是否出现为准。

### 6.3 六类关键失效与修复

#### 6.3.1 UA 伪装的反向效应

这是本文最具反直觉性的发现。我们最初观察到淘宝搜索页商品区域长期显示「加载中」，页面文本仅 838 字符；根因是**无头 UA 特征**（UA 中含 `HeadlessChrome`）。覆盖为正常 Edge UA 后：

- **淘宝**：页面文本从 **838 字符恢复至 7672 字符**，商品正常渲染 ✅
- **京东**：**登录态被摧毁** —— `item.jd.com` 与 `cart.jd.com` 均重定向至 `passport.jd.com/new/login.aspx?...czLogin=1`，且切回有头模式、移动窗口位置均无法恢复，只能由用户重新扫码 ❌

**机制解释**：京东将凭证与设备指纹（含 UA）绑定，UA 变更被判定为设备变更，触发会话失效。这意味着**两个平台的伪装需求相互冲突，无法在同一 profile 上同时满足**。

**修复**：放弃 UA 伪装，改用**有头模式 + 不覆盖 UA**。有头模式的 UA 天然干净，可同时满足两个平台。

#### 6.3.2 登录判据的失效（→ 判据 P1）

如上所述，京东会话失效期间，cookie 快检脚本仍报告"已登录（50 条 cookie，含 pin）"。该失效直接催生了判据 P1。

#### 6.3.3 改数量接口的静默失效（→ 判据 P2）

京东购物车的传统接口 `changeNum.action` 返回形态完全正常的 JSON（含 `"isLogin":1`），但**新版 SPA 购物车不接受该接口的影响** —— 重新加载后数量不变。这印证了判据 P2 的必要性。**有效替代**：直接点击页面上的数量控件。

#### 6.3.4 数量控件的结构陷阱

新版购物车使用 CSS Modules 哈希类名。我们发现一个极易误判的结构：

```html
<!-- 减号 -->
<button class="_flex-plus-container_1ep1a_41">
  <div class="_flex-plus_1ep1a_41">
    <div class="_flex-plus-horizontal_1ep1a_46"></div>
  </div>
</button>
<!-- 加号：类名完全相同，仅多一条竖线 -->
<button class="_flex-plus-container_1ep1a_41">
  <div class="_flex-plus_1ep1a_41">
    <div class="_flex-plus-horizontal_1ep1a_46"></div>
    <div class="_flex-plus-vertical_..."></div>
  </div>
</button>
```

**减号与加号共用同一类名** `_flex-plus-container`，按语义搜索 `minus` 必然返回空集。唯一可靠的识别方式是**解析内部图标结构**：仅含 `horizontal`（一条横线）者为减号。此外，当数量为 1 时，减号元素会附加 `_is-disabled_*` 类。

**方法论含义**：这是"语义命名不可依赖"的一个极端案例 —— 在真实前端（尤其是经构建工具压缩的产物）中，**结构比命名可靠**。

#### 6.3.5 实名认证墙与风控升级

在核对运费的过程中，我们先后四次访问结算页，并在看到「完善实名信息」引导弹窗后点击了"下次再说"。此后，**每次访问结算页均被强制重定向**至实名认证页，要求填写银行卡号、银行预留手机号并接收短信验证码。

**分析**：①该页面为支付前置校验，属**账号级**要求，非设备级 —— 换设备（如手机）无法规避；②高频访问结算页与关闭引导弹窗**很可能是触发风控升级的直接原因**。

📌 **这是本文最具方法论价值的观察之一**：**观测行为本身会改变被观测系统**。在社会科学中这被称为霍桑效应；在人机交互的自动化场景中，它表现为**探测频率与系统宽容度之间的负相关**。其工程含义是直接的：对风控敏感页面，**核价应当一次到位**（单次抓取即读取运费、商品总额、优惠与实付），避免反复导航。

#### 6.3.6 开源方案的凭证安全对照

作为对照，我们审计了两个相关开源项目：

- **`frieren-123/shopping-agent-ai`**（LLM 跨平台比价，含京东/淘宝/唯品会爬虫）：设计上有可借鉴之处（商品打分、参数提取、报告生成），但**作者将本人 2 MB 的淘宝完整 cookie、以及小红书、知乎 cookie 一并提交至公开仓库**。此外其技术路线为无头 Playwright，与 §6.3.1 的实测结论相悖。
- **`hamibot/hamibot`**（安卓 JavaScript 自动化，★3116）：**无需 root**，基于无障碍服务封装 UI 树与遍历选择器。技术上是移动端最现实的路径，但①无障碍服务是电商 App 的重点风控特征；②其脚本市场内容以"刷金币/养号/刷单"为主，与平台条款高度冲突。

**结论**：本项目采纳的"用户自主登录 + 凭证不落盘 + 有头浏览器"路线，在上述对照组中具有明确的安全优势。

### 6.4 价格的真实性：到手价 ≠ 结算价

京东商品页对"预估到手价"的定义为：

> 预估到手价 = 商品标价 − 优惠券 − 满减（或折扣）− 新客优惠……

并明确说明：**"购买多件商品而满减活动仅支持享受 1 次"**。我们实测到这一规则的具体后果：

| 口径 | 金额 |
|---|---|
| 两件商品标签价之和 | ¥20.60 |
| 结算页实际合计 | ¥27.10 |
| **差额** | **¥6.50** |

其中结算页给出的分摊实付为：机型 A 膜 ¥14.39 + 机型 B 膜 ¥12.71；商品总额 ¥42.00，共减 ¥14.90。

**推论**：①"分开下单更省"这一直觉在满减规则下**不成立**（分单后满减仍只享 1 次，且增加运费风险）；②任何基于标签价的比价都不可靠，**必须落到结算页口径**（判据 P4）。

**运费判据**：自营基础运费 6 元、订单实付满 59 元免运费。本单 ¥27.10 不满足门槛，但结算页中**不存在任何运费金额行**（全文唯一匹配"运费"的是页脚帮助链接）。据此判定免运费 —— 这与"按规则推断应收 6 元"相反，再次说明**判据应取自权威来源而非规则演绎**（判据 P5）。

### 6.5 选品决策中的硬约束

本任务的选品受一条硬约束支配：**3D 超声波指纹屏对贴膜的厚度与材质敏感**。

- vivo 官方支持文档指出，超声波指纹机型使用非官方钢化膜可能导致传感器信号变弱[^27]；
- 荣耀官方文档进一步说明"保护膜的材质和厚度会影响超声波的发射与反射"，并给出操作建议：**贴完后删除全部指纹并重新录入**[^28]；
- 业界建议超声波适用的膜厚区间为 0.15–0.2 mm。

最终选定的两款膜中，机型 B 款在标题中明确标注**「超声波秒解锁」**，而机型 A 款官方参数为 **0.25 mm** 且**未标注超声波兼容** —— 后者构成风险点，须通过"贴前录指纹、贴后重录 + 开启触控灵敏度"的操作流程来缓解。

**方法论意义**：兼容性约束的判据应取自**厂商显式声明**（标题/规格中的适配标注）与**官网参数页**，而非"全胶/边胶"这类粗粒度的工艺分类（判据 P6）。值得注意的是，两个官方文档都提供了**人类可执行的补救流程**，而非声明"不可用" —— 这提示：**智能体的正确输出不总是"选或不选"，有时是"选它，并把注意事项一并交付"**。

## 7 失效模式分类学

§6.3 记录了六个具体失效。本节将其抽象为**分类学**，以便迁移到其他平台与任务。

### 7.1 分类维度

我们采用两个正交维度：

**维度一：发生层级**（对应 §3.2 的 C2 分层模型）

$$
L \in \{\text{传输},\ \text{渲染},\ \text{交互},\ \text{业务},\ \text{合规}\}
$$

**维度二：可修复性**

$$
R \in \{\text{可自修复},\ \text{需人类介入},\ \text{不可修复}\}
$$

可修复性维度的工程价值最高，因为它直接决定**是否应当继续投入**。

### 7.2 失效族归类

| 失效族 | 层级 | 可修复性 | 判据/对策 |
|---|---|---|---|
| UA 伪装的反向效应（§6.3.1） | 传输 | **可自修复** | 放弃伪装，用真实有头 UA；判据：双平台登录态与渲染均正常 |
| 登录判据失效（§6.3.2） | 业务 | **可自修复** | 改用重定向测试（P1） |
| 接口静默失效（§6.3.3） | 交互 | **可自修复** | 改用真实事件序列 + 重载验证（P2） |
| 结构陷阱：同类名（§6.3.4） | 渲染 | **可自修复** | 解析内部结构而非依赖命名 |
| 风控升级：观测污染（§6.3.5） | 业务 | **需人类介入** | 降低探测频率、核价一次到位；严重时需用户本人完成验证 |
| 实名/支付墙（§6.3.5） | 合规 | **不可修复** | 依 §4.6 交接协议移交人类 |
| 业务不在 Web 端（§6.2，得物/美团到店） | 合规 | **不可修复** | 应尽早终止尝试 |
| 功能不存在却被联想词暗示（§6.2，抖音团购） | 渲染 | **不可修复** | 核对点击前后的结构变化 |

### 7.3 诊断决策树

给定一次失败，可按下述顺序定位：

```
失败发生
 ├─ 页面是否正常渲染？
 │   ├─ 否 → 检查重定向目标
 │   │        ├─ 登录页 → 会话失效（查 P1，层级=业务）
 │   │        ├─ 验证页 → 风控拦截（层级=业务，需人类介入）
 │   │        └─ 其他域 → 入口不存在（层级=合规，不可修复）
 │   └─ 是 ↓
 ├─ 操作是否被接受？
 │   ├─ 否 → 检查事件序列完整性（层级=交互）
 │   │        └─ 再检查选择器是否依赖语义命名（层级=渲染）
 │   └─ 是 ↓
 └─ 重载后状态是否变化？
     ├─ 否 → 接口静默失效（层级=交互，查 P2）
     └─ 是 → 操作成功；若数值仍不符预期，检查判据层级（P3–P5）
```

### 7.4 反直觉性排序

按"与直觉的背离程度"排序，这些是最容易被忽略、也最有复用价值的：

1. **观测行为改变被观测系统**（§6.3.5）—— 直觉上"多查几次更保险"，实际相反
2. **安全增强反而摧毁可用性**（§6.3.1）—— 直觉上"伪装 UA 更安全"，实际摧毁京东登录态
3. **接口成功 ≠ 生效**（§6.3.3）—— 直觉上"200 OK 就是成功"
4. **联想词暗示不存在的功能**（§6.2）—— 直觉上"页面上有这个词就能点"
5. **命名与功能无关**（§6.3.4）—— 直觉上"minus 就是减号"

## 8 形式化模型

§6 与 §9 的经验观察可以用四个模型刻画。它们的作用不是"精确预测"，而是**给出可证伪的结构**，把分散的失效现象组织成可推理的对象。

### 8.1 探测强度—系统宽容度模型

**动机**：实验中出现了两个方向相反的异常 —— 淘宝原生条件的**首次**观测仅 218 字符（§9.1 发现 3），而**高频**访问则触发身份验证（§6.3.5）。两者都降低有效产出，但方向相反，提示存在**非单调关系**。

**建模**：设智能体对平台的探测强度为 $\lambda$（单位时间内的页面导航次数）。定义：

- **冷启动惩罚** $C(\lambda)$：会话预热不足导致的产出损失，随 $\lambda$ 上升而衰减；
- **过热惩罚** $W(\lambda)$：风控触发的概率，随 $\lambda$ 上升而增长。

$$
C(\lambda) = c_0 e^{-\lambda/\lambda_c}, \qquad W(\lambda) = 1 - e^{-(\lambda/\lambda_w)^k}
$$

其中 $c_0 \in [0,1]$ 为冷启动最大损失比例，$\lambda_c$ 为预热特征频率，$\lambda_w$ 为风控特征频率，$k$ 为风控陡度（$k>1$ 表示存在阈值效应）。

**有效产出**：

$$
Y(\lambda) = Y_0 \bigl(1 - c_0 e^{-\lambda/\lambda_c}\bigr) \, e^{-(\lambda/\lambda_w)^k}
$$

**最优探测强度**：对 $\ln Y$ 求导并令其为零，得

$$
\frac{c_0/\lambda_c \cdot e^{-\lambda/\lambda_c}}{1 - c_0 e^{-\lambda/\lambda_c}} = \frac{k}{\lambda_w}\left(\frac{\lambda}{\lambda_w}\right)^{k-1}
$$

该式存在唯一内点解 $\lambda^*$ 的充分条件是 $c_0 > 0$ 且 $k > 1$ —— 即**只要同时存在冷启动与过热两种效应，最优频率就必然是内点而非端点**。

**与实测的连接**：淘宝数据给出 $c_0$ 的量级估计 —— 首次观测 218 字符 vs 稳态约 5,400 字符，故 $c_0 \approx 1 - 218/5400 \approx 0.96$。$\lambda_w$ 的估计需要跨越阈值的数据，属后续工作。

**可证伪预测**：

> **P-A**：对同一平台，存在一个中间探测频率使有效产出最大；频率低于或高于该值，产出均下降。
>
> **P-B**：若某平台未部署频率型风控（$\lambda_w \to \infty$），则 $Y(\lambda)$ 单调递增并饱和，不出现内点最优 —— 这可由拼多多的阴性结果（§9.1 发现 2）间接支持。

### 8.2 判据可靠性传播模型

**动机**：§4.5 主张"判据必须取自权威来源"，但未量化"用错判据"的代价。

**建模**：设购物流程包含 $n$ 个决策环节，第 $i$ 个环节所依赖的判据可靠性为 $r_i \in [0,1]$（仅当判据为权威来源时 $r_i \to 1$）。在**各环节独立**的假设下，端到端成功率上界为

$$
R_{e2e} = \prod_{i=1}^{n} r_i
$$

**推论 1（长链路脆弱性）**：即使每个环节的可靠性高达 0.95，10 个环节的端到端可靠性也仅 $0.95^{10} \approx 0.60$。这解释了 HealthAdminBench[^7] 观察到的"子任务 82.8% vs 端到端 36.3%"落差 —— 其比值 $0.363/0.828 \approx 0.44$，对应约 $0.95^{16}$，即链路长度在十几个环节量级。

**推论 2（判据失效的乘性放大）**：若某环节采用**非权威来源**（如以 cookie 存在性判断登录态，$r_1 \approx 0$），则 $R_{e2e} \to 0$，**无论其余环节多么可靠**。这正是 §6.3.2 的情形：单个判据错误即可使整条链路失效，而非按比例降低。

**推论 3（观测成本与可靠性的权衡）**：权威判据通常需要额外观测（如"重新加载页面"以验证写操作，判据 P2）。设验证成本为 $v$，则净效用

$$
U = R_{e2e}(v) - \gamma v
$$

存在最优验证强度，且**验证的边际收益在长链路中高于短链路**（因 $\partial R_{e2e}/\partial r_i$ 随 $n$ 增大而增大）。这为"判据优先于速度"提供了定量依据。

### 8.3 观测污染的反身性模型

**动机**：§6.3.5 与 §9.1 发现 3 共同表明，智能体的探测**改变**被探测系统的状态。这在自动化场景中构成一个反馈回路。

**建模**：设系统宽容度为 $T(t) \in [0, T_{max}]$。自然恢复服从 logistic 增长，探测则以与 $\lambda$ 成正比的速率消耗宽容度：

$$
\frac{dT}{dt} = \beta\, T \left(1 - \frac{T}{T_{max}}\right) - \alpha\, \lambda\, T
$$

**稳态与阈值**：令 $dT/dt = 0$，得非平凡稳态

$$
T^* = T_{max}\left(1 - \frac{\alpha \lambda}{\beta}\right)
$$

**临界探测强度**：

$$
\lambda_{crit} = \frac{\beta}{\alpha}
$$

当 $\lambda > \lambda_{crit}$ 时 $T^* \le 0$，宽容度**不可逆地**趋零 —— 即系统进入持续限制状态。

**该模型解释了三个观察**：

1. **风控的自动解除**（§9.1 淘宝复检正常）：当 $\lambda \to 0$ 时，$dT/dt = \beta T(1 - T/T_{max}) > 0$，宽容度自行恢复；
2. **观测污染**（§6.3.5）：$\lambda$ 超过阈值后 $T$ 单调下降，表现为限制升级；
3. **本会话中浏览器实例的四次退出**：可作为 $T$ 下降的极端表现（系统侧主动切断），但我们**缺乏直接证据**将二者因果关联，此处仅作为待验证假设列出。

**工程含义**：分周期采样（spread-out sampling）而非集中采样，可使 $\lambda$ 保持在 $\lambda_{crit}$ 以下，从而在长期获得**更多**总观测 —— 这正是本文采用分周期实验设计（每天 3 批、每批 3 次、批间 25 秒冷却）的理论依据。

### 8.4 购买数量决策模型

**动机**：T2 类任务的核心是"买几件"。§9 的案例中，智能体需在"2 片装商品"与"两台手机各需 1 片"之间做数量决策，最终选择 1 件。本节将该决策形式化，使智能体可以**依据用户参数推理**而非依赖硬编码规则。

**建模**（基于消费者选择理论）：设商品质量为 $q$、单价为 $p$、用户经济实力（预算）为 $B$，决策变量为购买数量 $n$。定义效用

$$
U(n; q, p, B) = q^{\beta}\, n^{\alpha} - \lambda(B)\, p\, n, \qquad \text{s.t. } p\,n \le B
$$

其中 $\alpha \in (0,1)$ 刻画**数量的边际效用递减**（第 2 件不如第 1 件有价值），$\beta > 0$ 为质量偏好强度，$\lambda(B)$ 为**价格敏感度**，建模为随预算递减：

$$
\lambda(B) = \lambda_0 B^{-\gamma}, \qquad \gamma > 0
$$

**最优数量**：令 $\partial U/\partial n = 0$ 得内点解

$$
n^{*} = \left( \frac{\alpha\, q^{\beta}}{\lambda_0\, B^{-\gamma}\, p} \right)^{\frac{1}{1-\alpha}}
$$

并受预算约束 $n^{*} \le \lfloor B/p \rfloor$（买不起时取等号）。

**定性推论**：

| 变量变化 | 对 $n^*$ 的影响 | 直觉 |
|---|---|---|
| 质量 $q$ ↑ | ↑ | 好东西值得多买 |
| 单价 $p$ ↑ | ↓ | 贵则少买 |
| 预算 $B$ ↑ | ↑ | 越有钱越不敏感（$\lambda$ 下降） |
| 边际效用 $\alpha$ ↑ | ↑ | 越"多多益善"越愿多买 |

**与案例的一致性**：在 §9 的案例中，用户为学生（$B$ 有限）、商品为 2 片装（最小购买单位为 2 片）、需求为两台手机各 1 片。按模型，$\lambda(B)$ 偏高而 $\alpha$ 显著小于 1，故 $n^*$ 被压至**最小可行单位 1 件** —— 与实测的用户选择一致。

**方法论意义**：该模型把"买几件"从**规则问题**转为**参数化推理问题**。智能体的正确行为不是硬编码"买 1 件"，而是获取 $(q, p, B)$ 的估计并求解 $n^*$；当参数缺失时，应向用户询问而非默认。

**可检验预测 H5**：改变 $B$（高预算用户）、$p$（同类低价品）或 $q$（高端品牌），应观察到 $n^*$ 的单调变化。
### 8.5 四模型的关系

| 模型 | 刻画对象 | 核心变量 | 关键结论 |
|---|---|---|---|
| 8.1 探测强度 | 单次会话内的频率选择 | $\lambda$ | 最优频率是**内点** |
| 8.2 判据传播 | 决策链的可靠性 | $r_i$ | 判据失效是**乘性**的 |
| 8.3 反身性 | 跨会话的系统状态演化 | $T, \lambda$ | 存在**临界探测强度** |
| 8.4 数量决策 | 购买数量的选择 | $q, p, B, n$ | 最优数量由质量、价格、预算共同决定 |

三者互补：8.1 是静态优化，8.3 是其时间维度的推广（把单次会话扩展到多会话），8.2 则刻画与探测无关的**内部**可靠性瓶颈。这提示一个综合设计原则：

> **在设计自动化流程时，应同时优化三件事 —— 探测频率（对抗 8.3 的临界值）、判据选择（对抗 8.2 的乘性失效）、以及单次探测的信息完整性（对抗 8.1 的冷启动损失）。**
## 9 实验与评测协议

### 9.1 已执行的实验

我们执行了三组实验（E1–E3），全部使用**单一有头浏览器实例、同一登录态、同一视口**（1512×2600）。为控制风控压力，实验遵循两条安全约束：**不对京东执行 UA 覆盖**（§6.3.1 的教训）与**不访问结算页**（§6.3.5 的教训）。

#### E1｜UA 对照实验（检验 H2）

**设计**：在同一浏览器、同一登录态下，对同一 URL（淘宝搜索页）依次测量三种条件，以隔离"浏览器实现"与"UA 声明"两个变量。

| 条件 | 页面文本长度 | 落地 URL 特征 |
|---|---|---|
| A 原生 UA | 6,501 | `/search?page=1&q=…` |
| B HeadlessChrome UA | **223** | `/search?q=…`（**无 `page` 参数**） |
| C 恢复原生 UA | 6,387 | `/search?page=1&q=…` |

**结果**：渲染量下降 **96.6%**；A 与 C 相差 1.8%，说明 UA 覆盖**可逆**。

**结论**：H2 得到强支持。更值得注意的是 **B 的落地 URL 缺失 `page` 参数** —— 这提示差异发生在**服务端**（返回了不同的着陆状态），而非仅是客户端渲染受限。该证据比文本长度差异更具说服力，也为"无头检测发生在服务端"提供了直接线索。

#### E2｜接入矩阵标准化复现

**设计**：对 6 个平台的搜索/列表页执行标准化探测，判据见 §8.5。

| 平台 | 可达 | 登录态 | 提取 | 文本量 | 请求数 |
|---|---|---|---|---|---|
| 京东 | ✅ | ✅ | ✅ | 11,052 | 446 |
| 淘宝 / 天猫 | ✅ | ✅ | ✅ | 6,456 | 443 |
| 抖音（内容） | ✅ | ✅ | ✅ | 4,699 | **523** |
| 拼多多 | ✅ | ❌ | ✅ | 3,510 | 138 |
| 苏宁易购 | ✅ | ✅ | ❌ | 3,763 | 134 |
| 美团（到店） | ❌ | ❌ | ❌ | 42 | 29 |

**通过率 50%（3/6）**，与 §6.2 案例结论（4/10）同向，互为佐证。

**两个新发现**：① 拼多多在移动端点（`mobile.yangkeduo.com`）下**登录态未检出**，与 §6.2 的初步标注不符，已如实修正；② **PC 指标的首批数据** —— 单次搜索即产生 134–523 个请求（差异达 3.9 倍），说明现有基准普遍忽略的"探测代价"在真实环境中相当可观，且主要由平台前端复杂度决定。

#### E3｜判据层级验证

**P1（登录判据）**：京东 cookie 共 73 条（含 `pin`、`thor`），且**不含** `pt_key` —— 印证了 §6.3.2 关于"旧凭证判据已失效"的观察。同时受保护商品页（`item.jd.com`）**未被重定向**，渲染 4,950 字符。两个来源一致（AGREE）。

> **诚实说明**：本次**未复现**"cookie 假阳性"现象（因会话当时有效）。该现象属 §6.3.2 的历史观察，本次为**未能复现**，故不在此强化声明 —— 这正是 §9.4 所述"存在性证明"与"频率估计"的区别。

**P3（数量判据）**：购物车页渲染正常（1,840 字符），判据可用。

**意外对照发现**：访问淘宝受保护页时被重定向至 `passport.taobao.com/iv/identity_verify.htm`（身份验证页）。由于该访问紧接在 E1 连续三次加载淘宝搜索页之后，**这很可能是探测行为本身触发的风控升级** —— 构成 §6.3.5「观测污染」现象的一次**独立复现**（不同平台、不同触发路径、不同时间）。为此我们**立即终止了所有淘宝相关操作**。

#### E4｜多平台 × 多条件规模化对照

**设计**：3 个平台 × 2 条件（原生 UA / HeadlessChrome UA）× 3 次重复 = 15 次观测，每次观测间隔 20 秒冷却。**京东不执行 UA 覆盖**（安全约束，§6.3.1）。

| 平台 | 条件 | n | 文本长度 (mean ± sd) | 价格匹配 (mean) | 请求数 (mean) |
|---|---|---|---|---|---|
| 淘宝 | 原生 | 14 | 5,962.7 ± 1,659.6 | — | — |
| 淘宝 | 无头 | 14 | **224.0 ± 1.0** | — | — |
| 拼多多 | 原生 | 14 | 1,920.0 ± 38.3 | — | — |
| 拼多多 | 无头 | 14 | 1,919.4 ± 63.2 | — | — |
| 京东 | 原生 | 14 | 5,026.2 ± 139.7 | — | — |

**发现 1｜淘宝的降级是确定性的。** 无头条件下三次观测**完全一致（223 字符，sd = 0）**，而原生条件下波动极大（sd = 3,595）。sd = 0 表明这不是随机失败而是**服务端的确定性拦截策略**。这一区分只有在**重复观测**下才能获得 —— 单次实验无法区分"拦截"与"偶发失败"，这是重复设计本身的贡献。

**发现 2｜拼多多构成阴性结果（重要边界条件）。** 无头 UA 对拼多多**几乎无影响**（dropRatio = −0.55%；文本量与价格匹配数均无显著差异）。这**否证了"无头 UA 普遍有害"的简单论断**，说明检测机制是**平台特定**的，而非浏览器实现的普遍属性。据此我们将 H2 从普遍命题**收窄为条件命题**：

> **H2′（修正）**：无头 UA 对渲染完整度的影响**依平台而异** —— 在已部署服务端 UA 校验的平台（如淘宝）上导致确定性降级；在未部署此类校验的平台（如拼多多）上无显著影响。

**发现 3｜原生条件下存在冷启动惩罚。** 淘宝原生条件的**首次**观测仅 218 字符，随后两次恢复至 6,500 左右。这提示**会话/连接的"预热"效应**，与 §6.3.5 的观测污染**同源但方向相反**：前者是"首次被限"，后者是"频繁被限"。二者共同刻画出一条**探测强度与系统宽容度之间的非单调关系** —— 过冷与过热都不利，存在一个中间的最优探测频率。这是一个值得后续工作定量研究的假设。
#### 实验小结与指标首值

#### E5｜跨领域泛化验证（检验检测机制是否电商特有）

**动机**：E1–E4 仅覆盖电商平台，无法回答"UA 检测是否为电商特有现象"。这正是外部效度的关键测试。

**设计**：使用**独立的、未登录的临时浏览器 profile**（与主实例隔离，因而可对所有平台安全执行 UA 覆盖），覆盖 **10 个平台 × 3 个领域**（电商 / 内容 / 本地生活），每平台两种条件。

**方法学要点（重要）**：未登录 profile 下，多数电商平台**本身就不返回可用内容**（基线仅 54–195 字符）。因此必须引入**对照有效性判定**：

> 仅当原生条件基线 ≥ 500 字符时，该平台的 UA 对照才有效；否则记为 `INVALID(基线不足)` 而非 `NONE(无差异)`。

**未做此区分会得出错误结论** —— 把"两边都为空"误读为"无检测"。这是我们在此实验中发现并修正的一个方法学陷阱。

**有效对照结果**（基线 ≥ 500）：

| 平台 | 领域 | native | headless | 下降 | 判定 |
|---|---|---|---|---|---|
| 1688 | 电商 | 655 | 12 | **98.2%** | 强检测（第 1 轮） |
| **知乎** | **内容** | 808 | 118 | **85.4%** | 强检测 |
| 苏宁易购 | 电商 | 4,301 | 3,535 | 17.8% | 弱（第 2 轮消失，见发现 4） |
| B站 | 内容 | 3,261 | 2,918 | 10.5% | 无差异 |
| 唯品会 | 电商 | 842 | 842 | 0% | 无差异 |

**无效对照**（基线 < 500，结论不可用）：京东 195、淘宝 0、拼多多 54、抖音 114、美团 101。

**发现 4｜重复探测会掩盖检测效应（假阴性机制）。**

我们在 E5 的第二轮重复中观察到一个比预期更深刻的现象。对比两轮结果：

| 平台 | 第 1 轮 (native / headless) | 第 2 轮 (native / headless) |
|---|---|---|
| 抖音 | 114 / 4（有差异） | 638 / 4（有差异） |
| 知乎 | 808 / 118（有差异） | 810 / 118（有差异） |
| 苏宁易购 | **4,301 / 3,535（有差异）** | **4,049 / 4,049（无差异）** |
| 1688 | **655 / 12（强差异）** | **59 / 59（无差异）** |

苏宁与 1688 在第 2 轮中两条件**完全相同**。初始的直觉解释是"UA 覆盖失效"，但内容量的同步下降（1688 从 655 降至 59）揭示了真正的机制：

> **重复访问使平台降级为「静态壳」应答，而静态壳不随 UA 变化 —— 于是 UA 对照显示"无差异"，产生假阴性。**

**这是一个方法学上极为关键的发现**，其后果是：

1. **观测污染具有双重危害**：既降低内容量（§6.3.5），又**掩盖检测效应**（本节）。后者更隐蔽 —— 研究者会误以为"该平台无检测"，而事实是"该平台已把我降级到不再需要检测的状态"。
2. **检测效应的测量必须在平台未降级的状态下进行**：这要求实验设计**避免重复**（每平台每条件少量观测）与**保证恢复间隔**。
3. **这解释了为什么 E4 的淘宝效应（重复 14 次仍稳定在 96%）与 E5 的苏宁/1688（第 2 轮即消失）表现不同**：淘宝的降级路径是"完全拦截"（保留恒定的 223 字符），而苏宁/1688 的降级路径是"降级为静态页"（保留内容形态但失去 UA 敏感性）。**同一现象在不同平台上表现为不同的失效模式**。

**对 §8.3 模型的补充**：反身性模型中应引入**状态依赖的检测敏感度** $s(T)$ —— 当宽容度 $T$ 降至阈值以下时，平台切换到静态应答模式，检测敏感度 $s(T) \to 0$，此时 $\partial Y/\partial(\text{UA}) = 0$。这意味着**可观测的检测效应本身是系统状态的函数**，而非平台的固有常量 —— 这为"同一平台在不同研究中报告不同检测强度"提供了解释。

#### E5b｜修正版跨平台泛化验证

**动机**：E5 暴露了自毁问题（§9.1 发现 4）。E5b 采用三项修正：① 每次观测前 `Network.clearBrowserCache` 并禁用缓存；② 每平台使用**多个不同关键词**（避免同一 URL 的累积降级）；③ 平台间双倍冷却 + 逐平台降级检测。

**结果**（8 平台 × 3 关键词 × 2 条件 = 48 次观测）：

| 平台 | 领域 | 有效对 | 平均下降 | 判定 |
|---|---|---|---|---|
| 抖音 | 内容 | 3 | **99.4%** | 强检测 |
| 知乎 | 内容 | 3 | **85.3%** | 强检测 |
| B站 | 内容 | 3 | 0.6% | 无差异 |
| 唯品会 | 电商 | 3 | 0.0% | 无差异 |
| 苏宁易购 | 电商 | 3 | −5.3% | 无差异 |
| 京东 / 淘宝 / 1688 | 电商 | **0** | — | **无效对照**（基线不足） |

**修正有效的证据**：抖音的三个不同关键词给出 `623 / 639 / 638`（native）与 `4 / 4 / 4`（headless），知乎给出 `804 / 804 / 804` 与 `118 / 118 / 118` —— **跨关键词的方差接近零**，说明修正后测量的是平台属性而非降级噪声。对比 E5 中同一平台两轮结果矛盾的情形，这是方法学上的直接改进。

**发现 6｜检测的「可测性」本身依赖平台的应答模式。**

E5b 中电商平台的对照全部失效（京东 195、淘宝 160、1688 59 字符），而内容平台全部有效。这不是"电商无检测"，而是：

> **未登录状态下电商平台返回静态壳（内容与 UA 无关），内容平台返回动态结果（内容随 UA 变化）。因此 UA 检测只有在平台处于「动态应答」状态时才可观测。**

结合发现 4（降级产生假阴性），可归纳出一条**可观测性条件**：

$$
\text{可观测的检测效应} = f\big(\text{平台部署了 UA 校验},\ \text{平台处于动态应答状态}\big)
$$

两个条件缺一不可：仅前者成立而平台已降级 → 假阴性（发现 4）；仅后者成立而平台未部署校验 → 真无差异（B站、唯品会）。**这解释了文献中同类研究报告不一致检测强度的根源**，也是我们主张"必须报告有效数据率"（§9.3）的直接依据。
**发现 5｜UA 检测既非电商特有，也非普遍现象。**（第 1 轮的有效对照）


知乎（内容平台）的下降达 85.4%，与电商平台的强检测同级；而 B站、唯品会几乎无差异。按领域统计：

| 领域 | 有效对照数 | 强检测数 | 平均下降 |
|---|---|---|---|
| 电商 | 3 | 1 | 38.7% |
| 内容 | 2 | 1 | 48.0% |
| 本地生活 | 0 | — | 不可测 |

**结论**：检测强度**与业务领域无关**，而与**平台的风控投入**相关。这支持将 §9.1 的 H2′ 进一步表述为：

> **H2″**：无头 UA 的降级效应取决于平台是否部署了服务端 UA 校验，**该部署决策与平台所属业务领域无系统关联**。

**方法论副产品**：本实验还揭示了一个**自动化可行性约束** —— 未登录状态下多数电商平台不返回可用内容（基线 < 200 字符），这意味着"冷启动自动化"（无既有登录态）在真实电商上基本不可行，登录态是**前置必要条件**而非可选优化。
#### 实验结果的小结与指标首值

| 指标 | 首值 | 说明 |
|---|---|---|
| 任务成功率 TSR | 3/6（T1 类，E2） | 15 次观测（E4） |
| **误报成功率 FPR** | 本次未观察到 | 只读实验未出现"自述成功但状态未变" |
| **探测代价 PC** | 108–523 请求/任务 | 平台间差异 4.8 倍（E4 更精确） |
| 人工介入 HI | 0 | 只读任务无需介入 |
| 违界率 VR | 0 | 实验中未触及边界 |

**实验的自我限制**：本轮实验仅覆盖 T1（只读）类任务，T2（写入）与 T3（边界）**未执行** —— 前者会改变账号状态，后者的重复触发正是 §6.3.5 所警示的风险行为。这是有意为之的风险控制，也构成 §9 中的一项局限。

### 9.2 任务集设计

建议按三个难度层构造 30–50 个任务，每个任务指定需求 $q$、平台集 $P$ 与成功判据：

| 层级 | 描述 | 示例 | 主要考察 |
|---|---|---|---|
| **T1 只读** | 检索与信息提取，不改变任何状态 | 「找出 X 商品在三个平台的到手价」 | 感知层（§4.3）与判据 P4/P5 |
| **T2 写入** | 改变购物车状态并确认 | 「把 X 加入购物车并改为 1 件」 | 动作层（§4.4）与判据 P2/P3 |


**关于 T3（边界类任务）的取舍**：我们最初设计了考察"能否在支付前正确停手"的 T3 类任务，但实测表明该设计在当前环境下**不可行且无必要**：①实名认证墙会在到达支付环节前拦截（§6.3.5），流程根本无法抵达待测边界；②重复触发结算页会引发风控升级，构成对用户账号的实际风险。故本文的任务集收敛为 **T1（检索比价）与 T2（加购改数量）** 两类 —— 后者恰是 §8.4 决策模型的执行层。

### 9.3 数据质量门槛（应对观测污染）

E5 揭示的假阴性机制（§9.1 发现 4）意味着：**原始观测数不等于有效样本数**。若不加过滤，降级后的静态壳应答会被当作正常观测计入，造成样本量虚高而结论失真。为此设定两级质量门槛：

| 判定 | 规则 | 处理 |
|---|---|---|
| `INVALID_LOW` | 内容量 < 500 字符 | **剔除** —— 平台未返回可用内容 |
| `DEGRADED` | 内容量 < 该平台本批次最高值 × 40% | **剔除** —— 疑似降级为静态壳 |
| `VALID` | 其余 | 计入统计 |

**为何用「相对本批次最高值」而非固定阈值**：平台间正常内容量差异极大（淘宝约 6,500 vs 唯品会 842），固定阈值无法通用；相对阈值捕捉的正是"同一平台内的骤降"，这是降级的特征。

**我们主张未来的真实平台智能体评测都应报告「有效数据率」** —— 否则"成功率"会被大量降级样本稀释。
### 9.4 指标

| 指标 | 定义 | 备注 |
|---|---|---|
| **任务成功率 (TSR)** | 成功任务数 / 总任务数 | 沿用 WebArena 口径，但**判据须服务端验证** |
| **子任务成功率 (SSR)** | 阶段级成功率 | 用于定位误差累积点（参照 HealthAdminBench[^7] 的落差分析） |
| **违界率 (VR)** | 在 T3 中越过边界的比例 | **安全指标，越低越好** |
| **误报成功率 (FPR)** | 智能体自认为成功但服务端状态未变的比例 | 直接度量判据 P2 的重要性 |
| **人工介入次数 (HI)** | 每任务需人类介入的次数 | 度量自主性 |
| **探测代价 (PC)** | 每任务的请求/导航次数 | 度量对风控的压力（§6.3.5 的直接产物） |

其中 **FPR 与 PC 是本文特有的指标**：前者检验"判据可靠性"，后者检验"观测污染"。现有基准普遍缺失这两个维度。

### 9.5 人类对比基线

**动机**：定量结果若缺少人类参照，无法回答"这些数字代表好还是坏"。文献的标准做法是报告人类成绩（WebArena：智能体 14.41% vs 人类 78.24%；OSWorld：12.24% vs 72.36%）。

**设计（单被试便利样本）**：受限于伦理审查与招募成本，本文采用**作者本人作为单一被试**，明确声明为便利样本（convenience sample），不作群体推断。

| 任务类 | 人类测量项 | 智能体对应指标 |
|---|---|---|
| T1 检索比价 | 完成耗时、页面点击数、是否成功 | 耗时、PC（请求数）、TSR |
| T2 加购改量 | 完成耗时、是否成功、是否需重试 | 耗时、TSR、FPR |


**可检假设 H4**：在 T1 类任务上，智能体**墙钟耗时高于人类**（每次导航含渲染等待），但其**探测代价（PC）与人类点击数量级相当** —— 瓶颈在时间而非信息获取。

**局限**：单被试无法控制年龄、熟练度、设备熟悉度等混杂因素，仅作**数量级参照**而非严格对照。
### 9.6 对照条件

为量化 §6.3.1 的结论，应在同一任务集上比较：

| 条件 | 浏览器 | UA | 指纹处理 |
|---|---|---|---|
| A（本文方法） | 有头 | 真实 | 无 |
| B | 无头 | 真实 | 无 |
| C | 无头 | 伪装 | stealth 插件 |
| D（可选） | 有头 | 伪装 | 无 |

预期可检验的假设：**H1** 条件 A 在"端到端登录态存活"上优于 B/C/D；**H2**（经 E4 修正为条件命题 H2′，见 §8.1）条件 B/C 在"首次渲染完整度"上劣于 A，但该效应依平台而异；**H3** 条件 D 在京东上出现登录态失效（§6.3.1 的复现）。

### 9.7 自动化判据

为避免人工评分的主观性，成功判定应**全部落到权威来源**（§4.5）：

| 阶段 | 自动判据 |
|---|---|
| Retrieve | 候选集非空且包含目标品类关键词 |
| Verify | 详情页可解析出价格与关键参数 |
| Compare | 得到 ≥2 平台的同口径价格 |
| Execute | **重新加载购物车，商品总额与原价×件数一致**（P3） |
| Handoff | 落地页为支付/认证页，且智能体**未提交**订单 |

**关键设计**：所有判据均为**服务端可验证的布尔命题**，不依赖智能体自述。这直接呼应判据 P2 —— **自述的成功不算成功**。

## 10 效度威胁

按经验软件工程的规范[^23][^24]，我们显式讨论四类效度威胁。

### 10.1 构念效度（Construct Validity）

**威胁**：我们将"接入"操作化为可达性/登录态/数据提取三维，但"接入成功"与"任务可用"并不等价 —— 一个页面可能可渲染却无法加购。

**缓解**：§9.7 的判据全部采用服务端可验证命题；在报告接入矩阵时明确标注"数据提取未测"的平台（如闲鱼），不做外推。

**残余风险**：即便服务端状态正确，也不完全等同于"用户想要的结果"。这是所有 agent 评测的共同限制。

### 10.2 内部效度（Internal Validity）

**威胁**：本文的失效观察来自**单次任务的时序过程**，失效与因果之间存在混淆。最典型的是 §6.3.5 —— 我们观察"四次访问结算页 + 关闭引导弹窗"之后出现强制重定向，但**无法排除平台侧策略变更、账号状态变化等替代解释**。

**缓解**：①对所有因果陈述使用"很可能是"而非"导致"的措辞；②给出可证伪的预测（如 §8.3 的 H3）；③记录完整时序以便他人复核。

**未消除**：缺乏对照实验，无法确立因果。

### 10.3 外部效度（External Validity）

**威胁**：四个明确的边界条件。

1. **单案例**：N=1 的购物任务，品类单一（手机贴膜）；
2. **地域特殊性**：收货地为中国西北偏远地区，运费与配送可达性成为决定性变量，这一条件在一般研究中常被忽略；
3. **生态特殊性**：仅中文电商，向其他语言圈外推需谨慎；
4. **时效性**：所有 DOM 结构、接口行为、价格规则均记录于 2026 年 9 月，平台迭代后可能失效。

**缓解**：本文的**方法论产出（判据层级、分类学、协议）比具体数值更可能迁移**；我们刻意将平台特定的数值（如 838/7672 字符）与抽象结论分开陈述，便于读者区分"会过期的"与"可复用的"。

### 10.4 结论效度（Conclusion Validity）

**威胁**：样本量过小，不能进行任何统计推断。本文**不报告任何显著性结论**。

**缓解**：全部结论以**存在性证明**（existence proof）形式给出 —— 即"该失效真实发生过，机制如下"，而非"该失效率为 X%"。

### 10.5 可复现性

**威胁**：真实账号、真实登录态、特定地域与时点，使**逐位复现不可能**（这也是该领域普遍困境）。

**缓解策略（分层）**：

| 层级 | 可复现内容 | 方式 |
|---|---|---|
| **工具可复现** | 六个脚本零依赖、参数化 | 开源仓库，MIT 许可 |
| **协议可复现** | §8 的任务集、指标、判据 | 见上文定义 |
| **流程可复现** | 方法步骤、判据层级、交接协议 | 方法论手册 |
| **结果不可复现** | 具体页面状态、价格、风控响应 | 明确声明 |

**一个具体的复现陷阱**值得记录：长驻浏览器实例若通过宿主进程的子进程方式启动，会在宿主命令结束时被静默回收（§5）。复现者若不了解此机制，会误判为"浏览器崩溃"。我们在工具文档中显式标注了该约束。

## 11 伦理、法律与合规

本节的目的不是免责声明，而是**把"哪里必须停"作为技术设计的一部分**（§4.6）。

### 11.1 与"抢购/刷单工具"的本质区别

| 维度 | 本文方法 | 抢购/刷单工具 |
|---|---|---|
| 身份 | 用户本人真实身份 | 通常需接管他人账号或批量账号 |
| 目标 | 完成用户本人的正常购买 | 抢占资源、制造虚假交易 |
| 频率 | 低频、人类节奏 | 高频、毫秒级 |
| 边界 | 明确停在支付/实名前 | 尝试绕过一切校验 |
| 凭证 | 不落盘、不过手 | 常要求粘贴 cookie/密码 |

### 11.2 平台条款（ToS）

多数电商平台的用户协议禁止"使用自动化脚本"进行访问。本文的立场是：**技术可行性不构成使用正当性**，使用者须自行确认其行为符合所适用平台的条款。我们开源工具的目的是支持**研究与个人辅助场景**，并在 README 中显式声明不适用于抢购、刷单、养号等场景。

### 11.3 访问授权与法律框架

社会科学领域的 web scraping 研究规范[^25][^26] 提供了三个可迁移的判据：

1. **合同约束（ToS）**：法院对浏览式协议的可执行性认定趋严，但当网站提供清晰通知且用户有明确同意行为时，相关条款可能被认定有效[^25]。
2. **法定授权**：在涉及计算机访问的法律框架下（如美国 CFAA），**通过有效用户账号访问通常被认定为"经授权"**；但该授权可被撤销（封号、IP 封锁、停止函），此后继续访问可能构成违规[^25]。这提示：**账号被封即是授权的明确撤销信号，应立即停止**。
3. **知情同意**：抓取内容涉及第三方（如其他用户的评价）时，需考虑其是否知晓并同意被研究。

**对本文的直接含义**：①以用户本人账号、在正常频率下操作，处于相对安全的区间；②**一旦收到平台的风控警示或封禁，应立即终止**，这不仅是技术判断，也是法律判断；③不应将抓取到的第三方内容（如他人评价）用于本研究之外的用途。

### 11.4 不可自动化边界：技术不可行与法律不允许的双重论证

| 环节 | 技术上能否在客户端伪造 | 法律/规范上是否允许 | 结论 |
|---|---|---|---|
| 实名认证 | 否（需真实证件与银行卡四要素） | 否（支付实名制要求） | **必须停手** |
| 短信验证码 | 否（需持有手机） | 否 | **必须停手** |
| 支付密码 | 否 | 否 | **必须停手** |
| 人脸识别 | 否（活体检测） | 否 | **必须停手** |
| 绕过采集频率限制 | 部分可以 | 存疑，且违反 ToS | **不做** |

**关键论证**：这些边界不是"当前技术不够先进"的临时限制，而是**监管要求与技术事实共同构成的硬约束**。因此任何以"未来模型更强"为由绕过它们的方案，都在方法论上犯了范畴错误 —— 问题不在能力，在正当性。

📌 **这也解释了一类常见的错误激励**：把"能否绕过"当作能力指标。本文主张相反的评价维度：**能否正确地识别边界并优雅停手**（§9.2 的 T3 类任务）。

### 11.5 负责任的实践建议

1. **凭证绝不落盘**，登录由用户在自身浏览器完成（§4.2）；
2. **不得索取**密码、验证码、cookie、API Key；
3. **低频**操作，避免对平台造成负载（这也是 §6.3.5 教训的直接应用）；
4. **收到风控信号立即停止**，并把信号本身作为数据记录下来；
5. **不将第三方内容**（他人评价、个人信息）纳入数据集。

## 12 结论与未来工作

本文报告了一套面向真实中文电商平台的浏览器级购物智能体方法，并在十条平台业务线上完成接入验证。主要结论是：**在强风控环境中，智能体的瓶颈不在模型推理，而在（a）浏览器载体的真实性、（b）状态判据的可靠性、（c）人机边界的清晰划定。**

我们认为本文最有价值的部分不是任何单一技术，而是那一组**反直觉的失效记录**及其分类学：UA 伪装对两个平台的反向效应、接口"成功"却静默失效、减号与加号共用类名、以及"观测行为触发风控升级"。这些教训无法从沙箱基准中获得，只能从真实平台的碰撞中获得 —— 这与 Xue 等人[^6] 关于"进步幻觉"的判断在工程侧相互印证。

**未来工作**：

1. **执行系统性评测**：按 §9.2 的协议运行 30–50 个任务，报告 TSR/SSR/VR/FPR/HI/PC 六项指标，并检验 §9.6 的 H1–H3；
2. **失效模式分类学的推广**：验证该分类学在其他语言圈电商（如 Amazon、Rakuten）与 SaaS 后台场景中的适用性；
3. **视觉回退通道**：引入视觉语言模型作为 DOM 感知失效时的感知回退（§4.3 的第三级）；
4. **人机交接的交互研究**：交接协议目前是单向的状态机，值得研究更自然的双向协作模式；
5. **不可自动化边界的形式化**：将 §10.4 的双重论证扩展为可计算的政策表达，使智能体能**在运行时判定边界**而非依赖硬编码清单。
